# Kindle 管理后台设计

参考 [Taste Skill 的后台应用流程](https://github.com/Leonxlnx/taste-skill/blob/main/skills/taste-skill/references/app-screens.md)。

## 方向

脚本抽取并选用 Framed sheet，seed `318214819`，没有重抽。选择理由：这是经常使用的家庭网络工具，节点、服务地址和设置需要快速定位，浅色框架与白色工作区适合并列阅读这些真实数据。

产品特征：Kindle 数据屏、飞牛 NAS、局域网 IP、HTTP/SOCKS5 端口、独立 WhatsApp 策略组、MTProto 密钥、机场订阅、延迟毫秒值、活动连接、账号用量设置。界面不生成示例流量、增长百分比或虚构健康评分。

视觉身份取自 Kindle 阅读器：页框形标志、偏冷的纸面与灰框，青色只用于流量曲线、线路状态和策略组下划线。采用 IBM Plex Sans 的 400/500/600 字重，WOFF2 字体内嵌，无在线字体请求；中文使用设备系统字体。布局保持原 Python + 原生 HTML/CSS/JS 技术栈，没有引入前端框架或运行时依赖。

## 五个视图的问题

- 运行概览：现在使用什么线路，服务是否在线？真实计数与当前策略组优先；本次访问开始采样的下载曲线明确注明没有历史数据。
- 代理节点：应该使用哪个节点？按策略组切换视图，保留原有搜索、延迟排序、单节点和整组测速、节点选择。
- 连接服务：设备应该填写什么地址？保留局域网、TG 和 WhatsApp 的真实连接信息，WhatsApp 外网地址仍可保存。
- 活动连接：流量正在去哪里？保留目标、协议、路径、流量及断开操作。
- 系统设置：怎样配置订阅与数据源？原 POST 表单、字段和后端校验保持原样。

## 布局和状态

228px 侧栏、48px 顶部框架、白色工作区、24px 组件间距。标题 22px，数字 28px，正文 14px，辅助文字 12px。桌面按两列组织相关信息；1100px 以下导航折叠，640px 以下双列内容转为单列，节点转换为两行条目。键盘焦点可见，导航具有当前视图标记，菜单可由 Escape 关闭，支持减少动态效果偏好。

统计数据来自原有受保护 API 的同一次状态更新，避免额外轮询。缺失值显示短横线，零保留为零；超过 30 秒未更新时标记数据过期。没有搜索结果时给出空状态。服务状态区分“已配置”与“运行中”，不将配置存在冒充协议握手成功。

## 验证与限制

- Python 语法、JavaScript 语法检查通过。
- Taste Skill 静态 lint：0 FAIL、3 WARN。代码/端口使用等宽字体；仅移动导航覆盖层使用阴影；短横线表示缺失数据。这三项是有语义的例外。
- 在无浏览器 DOM 环境中执行实际页面脚本，使用去除凭据的状态数据和模拟网络动作：验证五个视图、实时计数、策略组切换、搜索空状态、节点切换、WhatsApp 地址保存请求和原设置表单；无脚本错误。模拟动作没有修改 NAS 的节点或配置。
- 浏览器工具因无法可靠确认当前 Windows 浏览器 URL 而终止。因此没有完成真实浏览器截图检查，也没有运行依赖浏览器控制的 inspect.mjs；不声称已经通过 1440/768/390 屏宽的视觉验收或给出未经观察的设计评分。

表现层在 `admin_ui.py`，由 `app.py` 注入。`proxy_admin.py` 仅增加状态更新事件，控制接口及鉴权方式保留。
