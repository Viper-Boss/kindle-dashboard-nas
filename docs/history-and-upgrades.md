# 流量历史与组件升级

后台新增「流量统计」「组件升级」，使用网页内登录表单和可撤销的会话 Cookie，不再触发浏览器认证弹窗；沿用现有管理员账号。

## 每小时自动选择

通用代理的 URLTest 组及其引用的 provider health-check 都设为 interval: 3600、lazy: false、timeout: 5000、expected-status: 204；tolerance: 0。空闲时也会测试，结果更新后按可用节点延迟选路。已经建立的连接不会为此强制断开。Telegram、WhatsApp 独立 Selector 继续保持已验证的固定线路。

## 流量统计

- 按 Asia/Shanghai 自然日统计上传和下载；支持按日、按月、按年和客户端筛选，客户端备注、趋势及客户端 CSV 导出。
- 自启用起记录，不能恢复启用前的数据。SQLite 文件位于 data/traffic.sqlite3，长期保留日汇总；运行时计数只保留最近 35 天。
- Mihomo 传输计数钩子保留短连接，按传输发生的日期计数。TG/WhatsApp 在原有转发进程内按原始来源 IP 计数；内核中的转发容器流量被排除，避免重复。
- 每 10 秒累计写入 SQLite，按来源、进程 epoch、日期和客户端去重。容器重建保留数据库，正常关闭和升级前执行保存。突然断电可能损失尚未保存的一小段计数。
- 这是代理数据量，不是 NAS 网卡计费；TG/WhatsApp 包含客户端协议握手，通用代理为内核传输计数。路由器 NAT 隐藏来源时，多个设备会合并为同一 IP。IPv4 映射地址会归一化。
- 页首「全站今日、本月、今年」不受客户端筛选影响，趋势、服务和客户端列表均遵循筛选条件。
- 私有数据不提交 GitHub；迁移导出使用 SQLite 在线备份，而不直接打包正在变化的 WAL 数据库。

## 安装 NAS 升级服务

在项目目录使用 root 执行：

```sh
sudo python3 scripts/install-maintenance.py --project "$PWD" --current-commit <已部署的40位提交SHA>
```

要求 systemd、Docker Compose、出站访问 GitHub/镜像源和足够磁盘。维护服务为 kindle-maintenance.service；私有回退及构建状态存放 项目的 security-staging/maintenance-private（数据盘上），权限 700。Web 容器没有 Docker socket，仅能提交固定的 upgrade/rollback 请求。

「组件升级」显示后台、Mihomo、Python、Pillow、PyCryptodome、PySocks 的实际版本。手动检查读取固定仓库 Viper-Boss/kindle-dashboard-nas 的 main；升级该仓库锁定的组件组合，不会用不兼容的官方 latest 覆盖定制内核。

自动同步默认启用，每小时检查 main。仅部署对应提交的 security.yml 成功且已出现的 CodeQL 任务全部成功的版本。先下载并逐文件核对 Git blob，拉取锁定基础镜像，构建三个候选镜像，验证配置、程序导入与 Kindle 图像渲染，并用 Trivy 检查可修补漏洞。检查失败保持正式版本；应用阶段失败自动恢复上一版源码和镜像。升级会短暂重建代理，客户端需重连。

升级前备份源码、私有配置、SQLite 和镜像引用；部署保留现有 .env、订阅、密钥、代理配置及流量历史。手动回退保留当前历史数据并暂停自动同步，避免马上再次升级。重新开启可在页面操作。日志仅管理员可读，不接受任意命令、地址或文件路径。

迁移后请按上述命令在新 NAS 重新安装宿主机服务；迁移包不携带 systemd 安装状态。历史数据库也应定期通过私有迁移包另存。

## 网页登录

打开 /admin 后自动跳转 /login，支持密码显示、错误提示、7 天保持登录和退出登录。会话令牌仅保存在 HttpOnly、SameSite=Strict Cookie；数据库只保留其 SHA-256 摘要，退出立即撤销，初始化账号使用 .env；在网页自定义账号后使用数据库中的加盐口令哈希。默认会话 12 小时；失败登录按来源 IP 限制为每 15 分钟 10 次。管理后台及 API 仅接受网页会话，不再接受 Basic Authorization，也不发送 WWW-Authenticate。登录账号沿用 NAS 私有 .env 中 ADMIN_USERNAME / ADMIN_PASSWORD，不进入公开源码。通过 HTTPS 反向代理时可设置 COOKIE_SECURE=1。

构建依赖与镜像扫描先尝试直连，网络失败后再用现有代理重试，始终保留证书验证。迁移使用账号数据库的在线快照，保留自定义账号哈希并清除会话，迁移后使用修改后的账号重新登录。


## 修改登录账号

在「系统设置 → 登录账号」输入新用户名及当前密码；新密码、确认密码均留空时仅修改用户名，否则新密码需 12–128 个字符。保存后所有会话撤销，使用新账号重新登录。修改不影响 HTTP/SOCKS、Telegram 或 WhatsApp 客户端设置。

自定义口令使用 PBKDF2-HMAC-SHA256（随机盐、600000 轮）保存在私有 data/auth.sqlite3，不保留明文。修改后旧的 .env 初始化密码不会继续获得后台访问权限。遗忘自定义账号时，NAS 所有者可通过 SSH 在项目中执行 `sudo python3 scripts/reset-admin.py --use-env`，撤销自定义账号及会话，恢复到私有 .env 初始化账号。

## 日志容量

在「系统设置 → 日志容量」设置记录开关和 20–500 MB 的总轮转预算（默认 100 MB）。仅限制容量，不设置保留天数：四分之一给升级日志，其余分配给三个容器，各保留两份轮转文件。关闭时停止新增运行和升级日志，维护结果、流量历史仍保留；已有日志遵循容量预算。镜像、配置备份、安全扫描报告不计入日志预算。

应用日志设置由 NAS 维护服务执行，固定生成 Docker logging 配置，短暂重建三个服务；失败恢复旧配置。日志设置在后续升级中继续生效。后台没有 Docker socket，也不接受任意日志路径或命令。

## 版本显示

「组件升级」显示实际运行的通用代理内核（Mihomo）版本、Telegram/WhatsApp 共用转发程序的本项目版本及依赖版本。当前内核 v1.19.33-security.2 基于官方 v1.19.33，转发程序本项目版本为 1.1.0；转发版本不冒充第三方上游发布版本。

自定义账号启用后，不兼容账号存储格式的旧版本会被禁止回退，避免旧的初始化密码重新获得访问权限。维护任务运行期间暂不接受账号修改。
