Python 清单通过 pip-audit 2.10.1 审计，零条已知漏洞。镜像使用校验过官方 SHA-256 的 Trivy 0.76.1，在 ARM64 NAS 上扫描最终运行镜像，包含系统包与识别到的语言包，未添加漏洞忽略清单。完整 JSON 保存在 NAS 的私有审计目录，后续 GitHub Actions 报告作为构建产物保存。

仓库的历史 Dependabot 告警列表没有读取权限，不能把先前聊天中提及的“54/38 条”直接宣称为已逐条关闭。Python 包可以对应多条漏洞；告警数量多并不能推断它们来自容器。GitHub 告警取决于仓库依赖图和告警重新计算，NAS 重新构建本身不会关闭清单告警。

“零条已知漏洞”只描述本次数据库和扫描范围，不代表不存在未知漏洞。对应上游资料：[Dependabot 告警机制](https://docs.github.com/en/code-security/concepts/supply-chain-security/dependabot-alerts)、[依赖图支持的生态](https://docs.github.com/en/code-security/reference/supply-chain-security/dependency-graph-supported-package-ecosystems)、[Mihomo 源码](https://github.com/MetaCubeX/mihomo/tree/3f27ef39f8c96bbfbc8b0b9bb10f5c9ef60149d8)。
